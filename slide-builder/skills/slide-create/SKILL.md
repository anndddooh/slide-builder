# slide-create — Markdown原案 → 分かりやすいMarpスライド

Markdownで書かれた原案を、**内容を一切省略せず**、**分かりやすい**Marp形式のスライド
（`slides.md`）に変換するスキル。

このスキルは2フェーズで動く。同じスキルが状態を見て自動でフェーズを判定する。

- **前半（生成）** … `slides.md` 本体・Mermaid図・画像生成AI用の spec を作る。
- **後半（埋め込み）** … ユーザーが画像生成AIで作った画像を `slides.md` に埋め込む。

---

## 0. 設定（変更可能なパラメータ）

| パラメータ | 既定値 | 説明 |
|---|---|---|
| アクセント色 | `#2563EB` | スライドのテーマ色。`theme.css` の `--accent` を差し替える。 |
| 画像生成AI図の上限 | `8` 枚 | 手作業が要る図の最大数。Mermaid図は上限の対象外。 |
| 本文の目安 | 1スライド約200字 / 箇条書き6つまで | 超えたら次スライドに分割。 |

ユーザーがアクセント色や上限について希望を述べた場合はそれに従う。
特に指定がなければ既定値を使う。

---

## 1. 入力の特定

1. 引数または会話から **原案ファイルのパス** を特定する。不明なら必ずユーザーに尋ねる。
2. 出力先フォルダを次の規則で決める（**作成はまだしない**）:
   - `<原案と同じディレクトリ>/<原案のファイル名から拡張子を除いた名前>-slides/`
   - 例: 原案が `docs/proposal.md` → 出力先は `docs/proposal-slides/`
3. このスキルの同梱ファイルは `${CLAUDE_SKILL_DIR}/assets/` にある（後述の手順で参照）。

---

## 2. フェーズ判定

出力先フォルダの状態で、実行するフェーズを決める。

```
出力先フォルダが存在しない
        → 【前半】を実行（セクション3）

出力先フォルダが存在する
  ├ assets/fig-*.spec.md が1つも無い
  │     → 画像生成AI図は不要だったケース。slides.md は完成済み。
  │       「すでに完成しています」と伝えて終了（セクション6）。
  ├ assets/fig-*.spec.md がある & 対応する .png が1つでも欠けている
  │     → 【後半待ち】。欠けている図を一覧表示して待機（セクション5-A）。
  └ assets/fig-*.spec.md がある & 対応する .png がすべて揃っている
        → 【後半】を実行して埋め込む（セクション5-B）。
```

**重要な例外** — ユーザーが明示的に「作り直して」「原案を更新したので作り直したい」等と
言った場合は、フェーズ判定より優先して **セクション7（再生成）** に従う。
既存フォルダがあるのに前半をやり直すときは、ユーザー生成物を勝手に消してはならない。

---

## 3. 【前半】スライドと spec の生成

### 3-1. 原案を読み、構成を設計する

1. 原案ファイルを**全文**読む。
2. 章構成を設計する。**分かりやすさのために章立ての再編・順序変更・見出しの追加はしてよい**が、
   **原案の記述内容を削ってはならない**。要約して短くするのも禁止。すべての段落・文・表・
   コード・既存の図は、どこかのスライドに必ず収まること。
3. **原案に無い文章を新規に足さない**。まとめスライドや要約スライドは作らない
   （ユーザーが明示的に頼んだ場合を除く）。
4. 章の数を数える。**3章以上なら** 目次スライドと章扉スライドを入れる。2章以下なら入れない。

### 3-2. スライドへ分割する（1トピック1スライド）

- **1スライド = 1つの見出し / 1つの論点**。複数トピックを1枚に詰めない。
- 1スライドの分量の目安: **本文 約200字**、**箇条書きは6項目まで**。
- 目安を超えるときは次のスライドに分割し、続きのスライドの見出しは
  `見出し（続き）` とする。
- 長い表・長いコードブロックも、入りきらなければ分割してよい。
- 原案の文章は、箇条書き化・表化など**表現の整形**はしてよいが、情報は落とさない。

### 3-3. 図を入れる箇所を判断する

「言葉だけでは理解が辛い箇所」に図を入れる。判断基準は次の3類型:

1. **抽象概念・比喩** … 概念図・イラスト → **画像生成AI（fig）** で作る。
2. **複数要素の関係性** … 関係図・構成図 → 原則 **Mermaid（dia）** で作る。
3. **プロセス・時系列・手順** … フロー図・シーケンス図 → 原則 **Mermaid（dia）** で作る。

- Mermaidで表現できる図（フローチャート、シーケンス図、クラス図、状態遷移、ER図、
  ガントチャート、ツリー等）は**必ずMermaidを使う**。手作業ゼロで作れる。Mermaid図に枚数上限はない。
- Mermaidで素直に描けない図（抽象的なイラスト、比喩的なビジュアル、世界観の表現など）
  だけを **画像生成AI（fig）** に回す。
- 画像生成AI図（fig）は **既定で最大8枚**。候補が上限を超えたら、理解への寄与が大きい順に
  上限数だけ選び、残りは図なし（見出し＋テキスト）にする。どれを採用しどれを見送ったかを
  後半の報告でユーザーに伝える。
- 原案に**すでに画像がある**場合（`![](相対パス)`）は再生成せず、その画像ファイルを
  出力先の `assets/` にコピーして流用する。URL指定の画像はURLのまま使う。
- 原案に**すでにMermaidコードブロックがある**場合は、それを `dia` として再利用する。

### 3-4. 出力先フォルダを用意する

```
<原案名>-slides/
  slides.md
  assets/
```

`${CLAUDE_SKILL_DIR}/assets/placeholder.svg` を、出力先の `assets/placeholder.svg` にコピーする。

### 3-5. Mermaid図（dia）を作る

採番は `dia-01`, `dia-02`, … とする。各図について:

1. Mermaidコードを `assets/dia-NN.mmd` に書き出す（**ソースを残すことで後から編集できる**）。
2. 次のコマンドでSVGにレンダリングする（`npx` 経由なので事前インストール不要、初回のみ遅い）:

   ```bash
   npx -y @mermaid-js/mermaid-cli@latest \
     -i "<出力先>/assets/dia-NN.mmd" \
     -o "<出力先>/assets/dia-NN.svg" \
     -c "${CLAUDE_SKILL_DIR}/assets/mermaid-config.json" \
     -p "${CLAUDE_SKILL_DIR}/assets/puppeteer-config.json" \
     -b transparent
   ```

3. レンダリングに失敗した場合は、Mermaidコードの構文を見直して再試行する。
   それでも失敗するなら、その図はMermaidをやめてテキストやMarkdownの表で代替し、
   後半の報告でユーザーに伝える。
4. `slides.md` からは `assets/dia-NN.svg` を参照する（生コードは載せない。Marpは
   Mermaidを描画しないため）。

### 3-6. 画像生成AI用の spec（fig）を作る

採番は `fig-01`, `fig-02`, … とする。`${CLAUDE_SKILL_DIR}/assets/spec-template.md` と
`${CLAUDE_SKILL_DIR}/assets/figure-style.md` を読み、各図について `assets/fig-NN.spec.md`
を作る。spec ファイルは次の2層構造にすること:

- **YAMLフロントマター**（`---` で囲む） … スキル専用のメタ情報。
  `figure_id` / `target_slide` / `purpose` / `aspect_ratio: "16:9"` / `status: pending`。
- **本文** … `# 画像生成プロンプト` 見出し以下に、画像生成AIへの指示だけを書く。
  - 描いてほしい図の被写体・構図・登場要素・関係性を具体的に記述する。
  - 末尾に `figure-style.md` の内容（スタイル指定と厳守する制約）をそのまま展開する。
  - アスペクト比はメタ情報にも書くが、**本文プロンプト内にも「16:9の横長で」と明記**する。
  - **図中に文字を入れない**指示を必ず含める（ラベルはスライド側のテキストで付ける）。

### 3-7. `slides.md` を組み立てる

セクション8の記法に従って `slides.md` を書く。

- 先頭のフロントマターの `style: |` に、`${CLAUDE_SKILL_DIR}/assets/theme.css` の
  **全文を2スペース字下げして展開**する（外部テーマ登録を不要にし、`slides.md` 単体で
  どの環境のMarpプレビューでも正しく表示させるため）。
- アクセント色の指定があれば、展開時に `--accent` の値を差し替える。
- fig（画像生成AI図）のスライドでは、まだ画像が無いので **プレースホルダ**を参照する:
  画像行は `assets/placeholder.svg` を指し、その直後の行にマーカー
  `<!-- fig:fig-NN -->` を置く（後半がこのマーカーを目印に差し替える）。
- dia（Mermaid図）のスライドでは、最初から `assets/dia-NN.svg` を参照する。

### 3-8. ユーザーへ報告する（前半の締め）

次を分かりやすく伝える:

1. 生成したスライド枚数、章構成の概要。
2. Mermaid図は自動でレンダリング済みであること（枚数）。
3. **画像生成AIで作る図の一覧**。fig ごとに「`assets/fig-NN.spec.md` / 目的 / 対応スライド」。
4. ユーザーがやる手順:
   - 各 `fig-NN.spec.md` を ChatGPT にアップロードし、次の定型文を送る:
     > 添付ファイルの「画像生成プロンプト」以降の指示に従って画像を生成してください。
     > 冒頭の `---` で囲まれたメタ情報は無視してください。
   - 生成画像を `assets/fig-NN.png` という名前で同じ場所に保存する。
   - 全部そろったら、もう一度このスキルを実行する（後半が自動で走り、埋め込まれる）。
5. 図の候補を上限で見送った場合は、その旨と見送った図を伝える。
6. プレビュー/PDF書き出しは VS Code の Marp 拡張で行う旨を伝える。

## 5. 【後半】画像の埋め込み

### 5-A. 後半待ち（画像が一部未生成）

- `assets/fig-*.spec.md` を列挙し、対応する `assets/fig-*.png` の有無を調べる。
- **未生成の fig を一覧表示**する（`fig-NN` / 目的 / spec のパス）。
- `slides.md` は**変更しない**。「未生成の画像がそろったら再実行してください」と伝えて終了。

### 5-B. 後半実行（画像がすべて生成済み）

1. `assets/fig-*.png` がすべてそろっていることを確認する。
2. `slides.md` 内の各マーカー `<!-- fig:fig-NN -->` を探し、その**直前の画像行**の
   参照先を `assets/placeholder.svg` から `assets/fig-NN.png` へ書き換える。
3. 画像のサイズ・配置がスライド内で破綻していないか確認し、必要なら
   Marpの記法（`bg right:` の比率や `w:` 指定）を調整する。
4. すでに埋め込み済み（プレースホルダ参照が残っていない）なら、その旨を伝えて終了する。
5. 完成を報告する。VS Code の Marp 拡張でプレビュー/PDF書き出しができることを伝える。

---

## 6. すでに完成しているケース

出力先フォルダがあり `fig-*.spec.md` が1つも無い場合、画像生成AI図が不要だった
（＝前半で `slides.md` が完成している）。`slides.md` の場所を伝えて終了する。
作り直したい場合はセクション7に従う。

---

## 7. 再生成（既存フォルダがある状態でのやり直し）

既存の出力先フォルダがある状態で、ユーザーが作り直しを望む場合は、
**勝手に進めず**、必ず次の3択を提示して選んでもらう:

1. **画像を残して再構成** … ユーザーが作った `fig-*.png` と `dia-*.svg` は残し、
   `slides.md` と spec を作り直す。図の意味が変わらない範囲で既存画像を再利用する。
2. **全部作り直し** … フォルダの中身を破棄して前半を最初からやり直す。
   この場合も、削除の前に「`fig-*.png` を含めて削除します」と明示して確認を取る。
3. **中止** … 何もしない。

ユーザーが手作業で生成した画像（`fig-*.png`）を、確認なしに削除・上書きしては**ならない**。

## 8. Marpスライド記法リファレンス

`slides.md` はこの形式で書く。スライド区切りは `---`。

### フロントマター（先頭）

```markdown
---
marp: true
paginate: true
style: |
  （ここに theme.css の全文を2スペース字下げで展開）
---
```

### タイトルスライド（必ず先頭に1枚）

```markdown
<!-- _class: title -->
<!-- _paginate: false -->

# 原案のタイトル

## サブタイトル（あれば）
```

### 目次スライド（章が3つ以上のときだけ）

```markdown
<!-- _class: toc -->

# 目次

1. 第1章のタイトル
2. 第2章のタイトル
3. 第3章のタイトル
```

### 章扉スライド（章が3つ以上のとき、各章の先頭に）

```markdown
<!-- _class: section -->
<!-- _paginate: false -->

## Chapter 1

# 章のタイトル
```

### 通常スライド（テキストのみ）

```markdown
# スライドの見出し

- 箇条書き
- 箇条書き
```

### 通常スライド（図を横に置く: fig も dia も共通）

画像を右側に配置し、本文は左に流す。**`fit` を必ず付ける**こと。
`fit` が無いと画像は領域を埋めるよう拡大・切り取り（cover）され、図やイラストの端が
欠ける。`fit` を付ければ画像全体が収まる。`40%` は図を置く幅の割合。

```markdown
# スライドの見出し

![bg right:40% fit](assets/placeholder.svg)
<!-- fig:fig-01 -->

- 本文・箇条書き
```

dia（Mermaid）の場合は最初から実体を参照し、マーカーは不要:

```markdown
# スライドの見出し

![bg right:46% fit](assets/dia-01.svg)

- 本文・箇条書き
```

### 図が主役のスライド（中央に大きく）

図そのものを見せたいときは、図だけのスライドにする。
**サイズは原則 高さ `h:` で指定する。** スライドは高さが制約になるため、幅 `w:` だけで
指定すると縦長の図がスライド下端からはみ出す。見出しと余白を除いた表示領域は
およそ高さ480px。図だけのスライドなら `h:480` 程度、他の要素と同居するならさらに小さく。

```markdown
# スライドの見出し

![h:480](assets/dia-02.svg)
```

明らかに横長の図は幅 `w:` 指定でもよい（例: `![w:1080](assets/dia-02.svg)`）。

fig を中央大きく置くときも、前半ではプレースホルダ＋マーカーにする:

```markdown
# スライドの見出し

![h:470](assets/placeholder.svg)
<!-- fig:fig-02 -->
```

> **Mermaidのレイアウト** — フロー図など要素が多い図は、`graph TD`（縦）より
> `graph LR`（横）の方が 16:9 スライドに収まりやすい。フロー図は原則 `LR` を使う。

## 9. 出力ディレクトリ構造（最終形）

```
<原案名>-slides/
  slides.md            テーマCSSインライン済み・自己完結。Marp拡張で設定ゼロ表示。
  assets/
    placeholder.svg    未生成figの仮表示（同梱物のコピー）
    fig-01.spec.md      画像生成AI用プロンプト（YAMLメタ＋本文）
    fig-01.png          ← ユーザーがChatGPTで生成して配置
    dia-01.mmd          Mermaidソース（編集用に保存）
    dia-01.svg          mmdcでレンダリング済み（slides.mdが参照）
```

`fig-` = 画像生成AIで作る図、`dia-` = Mermaidで作る図。
